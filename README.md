# 전기기능사 학습실 ⚡

전기기능사 자격증 취득(필기/실기)을 위한 핵심 요약, 이론 정리, 그리고 기호 암기 도구들을 관리하는 나만의 학습 공간입니다.


## 📅 학습 과목 개요

전기기능사 필기는 크게 3가지 과목으로 구성되어 있으며, 각 과목의 기초는 **전기 기호와 단위를 완벽히 숙지하는 것**에서 시작합니다.

1. **전기이론**: 정전기, 자기, 교류 회로 등 기초 물리 및 회로 해석 (수학적 개념 다수)
2. **전기기기**: 발전기, 전동기, 변압기, 정류기 등의 원리와 특성 (기기별 구조 및 기호 필수)
3. **전기설비**: 전선, 배선 기구, 접지, 배선 공사 등 실무 규정 (KEC 한국전기설비규정 기반, 기호 암기 필수)

### `summaries.html` 은 손으로 고치지 않는다

마크다운 6개(`핵심.md` · `Theory_Summary.md` · `Machinery_Summary.md` · `Facility_Summary.md` ·
`학습계획.md` · `공식_사용처.md`)와 **`문제은행.json`** 이 원본이고, HTML 은 **스크립트가 만든다.** `Theory_Extra_전기기사대비.md` 처럼 그 3개에
안 든 문서는 요약집에 반영되지 않는다 — 기능사 범위 밖 참고 자료라 일부러 뺐다.
하나라도 고쳤으면 다시 돌린다:

```bash
python build_summaries.py
```


### 문제은행을 고칠 때

문제·보기·정답·해설의 원본은 **`문제은행.json` 하나다.** 요약집의 '문제풀이' 탭은
빌드가 이 파일에서 만들어 내므로, **HTML 안의 문제를 손으로 고치지 않는다.**
고쳤으면 `python build_summaries.py` 를 다시 돌린다.

빌드가 문제은행을 검사해서 알려주는 것 두 가지 — **뜨면 그냥 넘어가지 말 것.**

* **id 가 겹치는 문항** — 누적 오답 기록이 두 문제에 섞여 엉킨다.
* **정답 번호가 보기 범위를 벗어나거나 보기가 4개가 아닌 문항** — 화면에서 정답을 못 고른다.

수식은 TeX 를 쓰지 않는다. **유니코드로 바로 적는다**(Φ · √ · ² · × · Ω · μ) —
빌드가 이 글자를 그대로 화면에 넣기 때문이다.

> 문제는 요약집 3개에서 뽑은 **기출 '유형'** 이다. 실제 회차 문제를 옮긴 것이 아니므로
> **"기출 원문"이라고 말하지 않는다.** 대신 모든 답이 우리 문서와 대조되고,
> 틀린 자리가 곧 다시 볼 절이 된다(각 문항의 `src`).

> **⚠ 돌린 뒤 마지막 줄을 볼 것 — "모르는 수식 명령" 경고가 뜨면 그냥 넘어가지 말 것.**
> 이 스크립트는 TeX 를 직접 HTML 로 바꾸는데(외부 라이브러리 없음), 모르는 명령은
> **화면에서 통째로 사라진다.** 실제로 `\sigma` 를 몰라서 $E = \sigma/2\varepsilon_0$ 가
> `E = 2ε₀` 로 나온 적이 있다 — **틀린 공식보다 나쁘다. 보는 사람이 이상한 줄도 모른다.**
> 경고에 뜬 기호는 `build_summaries.py` 의 `SYMBOLS` 에 추가하고 다시 돌린다.
> (2026-09-04 에 `\sigma` `\oint` `\Leftrightarrow` `\cdots` 를 이렇게 찾아 고쳤다.
> `\Leftrightarrow` 는 8군데에서 안 보이고 있었다.)

> **⚠ 굵게(`**`)는 한 줄 안에서 닫을 것.**
> 인용문(`>`)과 목록은 **줄마다 따로** 처리하기 때문에, 굵게가 줄을 넘으면 닫히지 않고
> 화면에 별표가 그대로 보인다. 이것도 빌드가 잡아서 알려준다.

### 수식은 한 줄에 하나씩 쓴다

`$$ ... \qquad ... $$` 처럼 한 줄에 공식을 두세 개 욱여넣으면 폰에서 읽기 어렵다.
**조건을 위에 붙이고 공식을 따로 놓는다** — 교재와 같은 모양이 된다.

```markdown
**바깥** — $r \ge R$
$$E = \frac{Q}{4\pi\varepsilon_0 r^2}$$

**안** — $r < R$
$$E = 0$$
```

### 설명은 접이식(`:::`) 안에 넣는다

본문에는 **공식과 시험에 그대로 나오는 사실**만 두고, "각 항이 무엇인가 · 왜 그런가 ·
손잡이"는 접이식 안으로 넣는다. 안 그러면 시험 직전에 훑기가 나빠진다.

```markdown
::: 왜 이 식인가 — 각 항이 무엇인지도 여기
설명 · 표 · 인용 · 목록 · 수식 아무거나 쓴다.
:::
```

`:::` 뒤에 쓴 것이 접힌 줄의 제목이 되고, 안 쓰면 "왜 이 식인가"가 된다.
**안쪽도 본문과 같은 규칙으로 그려지므로 표를 넣어도 된다** (2026-09-07 에 고쳤다 —
그전에는 문단과 목록만 처리해서, 접이식 안의 표가 화면에 `| 글자 | 뜻 |` 파이프
글자 그대로 보였다. 표인 줄도 모르고 지나간다).
**단, 안쪽에 `##` 는 쓰지 않는다** — 목차 앵커가 바깥과 겹친다.

### 공식만 던지지 않는다 — 항상 외우기 쉬운 형태를 같이 붙인다

**사용자가 명시적으로 요구한 원칙이다: "무조건 내가 외우기 편하게 해야 해."**
공식·수치를 새로 추가할 때 정확하기만 해서는 안 되고, 아래 중 하나는 반드시 곁들인다.

* **니모닉(축약어)** — 예: "코뒤콘앞"(코일은 전류 뒤짐, 콘덴서는 앞섬), "우발좌전"(오른손=발전기),
  "유코무싸"(유효=cos, 무효=sin), "철도는 육오(6.5)"
* **직관적 비유** — 예: 피상·유효·무효전력을 "맥주잔"(전체/물/거품)으로
* **계산 없이 찍는 패턴** — 예: R-L-C 임피던스가 3-4-5·6-8-10 배수, 동기속도는 7200 나누기
  (이런 것들은 `빠른풀이_꼼수.md` 로 따로도 모은다)

새 내용을 추가하면서 이걸 빠뜨리면 반쪽짜리다 — **정확한 공식 + 외우는 손잡이**가 한 세트.
